## Separation principle (read first)

RATIFIED (charter Constitutional invariants; A1-D11; loop-directive effect invariants): Runtime governs whether a precisely described effect may occur; the executor, VM, container runtime, host OS, and network controls enforce isolation. Neither layer substitutes for the other. Every boundary below names which side it sits on, and every control states whether it is an authorization check (Runtime, before/at spend) or an enforcement mechanism (environment, during/after effect). Confusing the two is treated as a finding, not a design option.

## Protected assets

RATIFIED (charter Objective; D2/D4/D7/D8) + INFERRED (enumeration from ratified text): (1) Runtime-issued `IPermission` authority and the spend ledger; (2) canonical effect descriptors and their hashes; (3) authoritative host repositories and their HEADs; (4) provider credentials and model budget; (5) source confidentiality by data class; (6) worker-output patch integrity; (7) receipt/evidence chain completeness; (8) signing/trust roots. No asset is observable in a live Fleet configuration today — all enforcement below is specified, NOT_TESTED.

## Actors

RATIFIED (charter D18/D23; discovery authority model): owner (human, grants Gate 2/3, repo creation, spend, disclosure); coordinator/foreman (proposes, reconciles, judges; mints nothing — D23); Runtime/Gateway (decides, spends, receipts); executor / model gateway / Promotion Actuator (audiences that exercise effects, never widen them); worker (untrusted model-controlled code; holds no credentials); reviewers + offline verifier (independent evidence consumers); external provider (untrusted cost/usage counterparty); attacker (any party attempting the faults in GMF-NEG-001–GMF-NEG-066, including a compromised worker, gateway, or tool server).

## Trust boundaries

- B-001 — Runtime authorization boundary (authorization side). What crosses: exact proposed descriptor in; `IPermission` + spend + pre-effect receipt out. Rule — RATIFIED (D2/D3/A1-D6): only Runtime-issued `IPermission` confers authority; envelope, role, receipt, evidence, or coordinator judgment confer none. Controls: atomic validation/consumption/attempt-record/reservation/slot/receipt commit (CTR-010); effect-time revocation/expiry/audience/nonce/descriptor/lineage checks. Independent observer: receipt-store reader + offline verifier path (CTR-013), never the requestor's own claim. GAP: durable transaction does not exist yet. Downstream: P1 (contract), P2A–P2C (build). Denials: NEG-004–NEG-009, NEG-059, NEG-060.
- B-002 — Source / materialization boundary (enforcement side, authorized at B-001). What crosses: content-addressed source in (post-spend only); patch/evidence artifacts out. Rule — RATIFIED (A1-D5/A1-D9/D8): pre-spend preparation is blank and source-free; post-spend bootstrap materializes, verifies manifests, closes the channel, then permits cognition; never a host bind mount. Controls: manifest verification before cognition; traversal/unsafe-form rejection; TOCTOU detection. Independent observer: manifest verifier + disposable-root escape scanner owned by harness (P4B). GAP: executor, manifests, and scanner all absent (MAP-006; CTR-006/CTR-009). Downstream: P1, P4B. Denials: NEG-002, NEG-042–NEG-047.
- B-003 — Process-tree boundary (enforcement side). What crosses: one root process start (post-spend); termination signal in; terminal evidence out. Rule — RATIFIED (A1-D5/A1-D17): one satisfied spend starts at most one isolated root process tree; any bootstrap/manifest/launch/runtime failure consumes the permission and terminates the whole tree with no retry under it. Controls: descendant accounting, resource/policy enforcement, independent whole-tree-death proof. Independent observer: host-level process-table snapshotter operated by harness (P4B), never worker self-report. GAP: no executor, no observer implementation. Downstream: P4B. Denials: NEG-001, NEG-010, NEG-024, NEG-048, NEG-049.
- B-004 — Isolation-tier boundary (enforcement side). What crosses: attestation evidence in; eligibility decision out. Controls: `ExecutionEnvironmentIdentity` binding + independent pre-spend attestation match. Independent observer: attestation verifier + independent isolation review (human). GAP: identity schema, VM selection, and reviewers all pending (DR-003). Downstream: P1, P4B (+ human review). Denials: NEG-001, NEG-010.
- B-005 — Worker network boundary (enforcement side). What crosses: explicitly named internal-gateway traffic only. Controls: default-deny namespace egress/DNS, internal names only, destination pinning. Independent observer: harness packet capture on the disposable-bridge interface (P3B/P4B). GAP: gateway, policy, and tap all absent. Downstream: P3B, P4B. Denials: NEG-003, NEG-025, NEG-026.
