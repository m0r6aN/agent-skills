## Localized defect and minimum guard

The frozen attempt-03 `script-snapshot.ps1` computes `deletedPaths` by unioning worktree-deleted and index-staged-deleted Git paths in `Get-GitBaseline` (around lines 437–443). `Invoke-SourceCapture` then emits `ABSENT_TRACKED` / `ABSENT_NOT_COPIED` for **every** path in that union (around lines 527–535), without checking actual worktree presence. A path deleted from the index can have a newly recreated, untracked regular file on disk. In that case the inventory/copy path would preserve the file's bytes, while the combined manifest would also declare the same relative path absent. Index state is not physical-source absence. The fixture did not exercise this condition. An accepted copy-only custody record must not make both claims.

The narrow root-cause correction to be proved is: retain staged and unstaged Git deletion flags as separate exact-path **index/status facts**, but derive each `ABSENT_TRACKED` entry only from a no-follow, actually observed worktree absence at an eligible traversed path. Use the same decision helper in the pure in-memory F preflight regression and prospective S manifest construction. Never infer physical absence merely because a path is missing from an inventory beneath an excluded ephemera directory, opaque external link, or internal-link stop boundary. Do not descend into or resolve those boundaries to settle the question. Preserve their boundary classification and Git facts; if their unresolved presence prevents a truthful accepted manifest, fail closed rather than fabricate an absent entry. A recreated on-disk regular file must be copied once with its actual bytes/hash and must not receive a duplicate absent entry.

Before **any future fixture layout or candidate invocation**, the same candidate helper must pass and create-once-record a pure in-memory matrix, with exact relative-path expected entries/counts:

| Case | Required result |
|---|---|
| Staged deletion; same path recreated as an observed regular file | Preserve staged-deletion Git fact; one copied-file entry; **no** absent entry. |
| Staged deletion; worktree path actually observed absent | One `ABSENT_TRACKED` entry; no copied-file entry. |
| Unstaged deletion; worktree path actually observed absent | One `ABSENT_TRACKED` entry; no copied-file entry. |
| Both staged and unstaged deletion indicators for one absent path | One deduplicated absent entry, with both Git facts retained. |
| Deleted index path coinciding with an existing excluded directory or opaque/internal link boundary | Preserve boundary and Git facts; no false absent child entry and no traversal or target resolution. |
| Deleted index path below any nontraversed excluded/link boundary | Presence is unobserved, **not** absent; fail closed if reconciliation is otherwise impossible. |

Supply that observed inventory path and a representative Git-quoted/escaped rendering of that same path (surrounding double quotes, with é represented by UTF-8 octal escapes) as separate in-memory inputs; the quote characters belong to Git's rendering, **not** to the on-disk filename. It must never turn an encoding, quoting, or path-identity mismatch into a fabricated absent entry.
