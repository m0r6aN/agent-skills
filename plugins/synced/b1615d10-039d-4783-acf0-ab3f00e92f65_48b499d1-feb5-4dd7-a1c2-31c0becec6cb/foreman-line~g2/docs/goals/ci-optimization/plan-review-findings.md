## Verbatim findings

F1 — *Pin parcel worktree base and sequencing against open PR #122's edits to the same surfaces* (blocker, conf 0.9): The charter sequences CI-P1→CI-P2 (charter.md:54) but never states where parcel worktrees are cut from. Verified live: open PR #122 (dev→main) modifies all three owned surfaces (`git diff main...origin/dev --stat` shows 23 insertions/19 deletions across foreman-line-ci.yml, foreman-line-ci.mjs, foreman-line-ci.test.mjs: actions v4→v6, sweep-list churn), and the dev tree additionally deletes the `hybrid-routing` package that origin/main sweeps. Ruleset main-pr-gate (id 22369510) gates only PRs into `~DEFAULT_BRANCH` = `main`, so parcel PRs must target `main` to be gated at all — gate-1 says this but no document says what to branch FROM. Branching from `dev` entangles a parcel PR with PR #122's ~32 commits and its surface edits; branching from `main` builds against the 20-package/hybrid-routing state PR #122 is about to delete, guaranteeing conflicts. Disposition: fix — name the base ref (e.g. origin/main at cut time) and an explicit rebase/ordering protocol relative to PR #122.

F2 — *Name the reuse-evidence mechanism; workflow token cannot read run history as declared* (blocker, conf 0.85): CI-P1's core requires verifying "a prior successful run" and emitting a "source run" — i.e., fetching GitHub Actions run/check conclusions, the only unforgeable source of "prior success". Verified on disk: `.github/workflows/foreman-line-ci.yml` declares `permissions: contents: read` only, which grants no `actions` scope; any Actions-API lookup with that GITHUB_TOKEN returns 403, so the reuse path cannot retrieve its evidence as the workflow stands today. Alternative evidence stores are all worse and unpinned: in-repo evidence files are forgeable by the very PRs they gate; cache entries are branch-scoped and evictable; artifacts need actions:read too and have retention limits. Fork PRs get read-only tokens — they can read once `actions: read` is added but cannot write shared evidence. Disposition: fix — pin evidence = Actions-API conclusions of a prior run at equivalent content hashes, record the required `permissions` addition, state fork-PR behavior.

F3 — *Restate required-check identity as two contexts; "one final required check" deadlocks the gate* (major, conf 0.95): Ruleset main-pr-gate requires BOTH contexts `test` AND `integration-report` (strict policy). The charter speaks of the required check in the singular throughout (Invariant 4, CI-P1 AC4, CI-P2 AC5). A literal CI-P2 collapse to a single check leaves one required context unreported; strict policy then makes the PR unmergeable regardless of the aggregator's verdict. Disposition: fix — both context names report on every head; the aggregation verdict surfaces through `test`, `integration-report` mirrors it (as today).

F4 — *Define "eligible packages" for CI-P2 discovery; 8 tracked packages with check scripts sit outside the sweep* (blocker for CI-P2, conf 0.95): 27 `plugins/foreman-line/*/package.json` per tree vs 19 (dev) / 20 (origin/main) swept; membership churn (`hybrid-routing` deleted on dev; `kernel-import` dev-only); the 7–8 unswept packages ALL define test/typecheck/lint scripts. Literal dynamic discovery sweeps all 27 into the merge gate (previously-ungated packages can suddenly fail the required `test` context); a discovery reproducing the frozen list is fake dynamism. "Complete package coverage" is already false today. Disposition: fix — pin the eligibility rule and its rationale, reconcile 19/20/27 explicitly.

F5 — *Give CI-P2 AC6 a pass criterion, queue-separated methodology, and a runner-minutes bound* (major, conf 0.9): AC6 demands only "Compare elapsed time and runner minutes with the baseline" while AC4 pre-authorizes full install per shard under the committed barrier "every install must succeed before any check" — each shard reinstalls everything, multiplying minutes; failing runs measure install-only spans; created→updated spans are queue-polluted (~73 min queue observed). A builder can double billed minutes and compare noise. Disposition: fix — bind AC6 to a direction and the queue-separated measurement.

Disposition: fix — pin emitted fields, require a falsifiable negative demo, say both contexts.
