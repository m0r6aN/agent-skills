## F1 — A1.8's status line is itself a stale self-reference (INFO, but pointed)

The document says it is uncommitted; it was committed in `7fa0ddf`. The commit message is
accurate that ratification did not occur, so no authority was manufactured — the defect is
confined to the status line.

Worth naming rather than quietly fixing: this is a stale self-description inside the
amendment whose stated purpose is retiring stale self-references, and it is the third time in
this goal that the artifact a future `/goal resume` trusts first was wrong about its own state
(the others: the loop directive saying STOPPED while running, and FK-P0 rework rounds recorded
in commit messages with no findings on disk). The pattern is not carelessness about content —
it is that **status lines are written once and then outlive the state they describe**, which is
the same defect class A1.8 diagnoses in prose that enumerates a binding set.

## F2 — §4.1's rule is ambiguous, and both amendments to §4.1 sit in the ambiguity

§4.1 states: *"Appending a row is the only way to change the binding set. An amendment
document that has not produced a row here is a proposal, whatever its own status line says."*

Those two sentences do not say the same thing, and the gap between them is where A1.8 and
A1.9 both land:

- **Read as "changed the binding set ⇒ needs a row":** neither qualifies. A1.8's own scope
  limits say it adds no decision and alters no parcel, scenario, or exit criterion. A1.9's
  commit message argues the same and adds explicitly that "adding a column is not appending a
  row." Under this reading both are fine and nothing needs doing.
- **Read as "is an amendment document ⇒ needs a row":** both are proposals, and §4.1 —
  installed by one and amended by the other — is a section that disclaims its own authority
  while §4 preamble and §10 route the binding-set question through it.

A1.8's known-defect section, and the two independent reviewers who found it, take the second
reading. I agree with them, because the first reading makes the rule unenforceable: whether an
amendment "changed the binding set" is exactly the judgment the ledger exists to remove from
prose, so a rule that applies only when someone has already made that judgment governs nothing.

**Practical blast radius is small and should not be overstated.** D1–D21 are each rowed by
`L1`, `L2`, or `L3`, so **no locked decision is unsupported.** What is provisional is the
*mechanism*, not the decisions, and the cost falls on the next amendment that needs to cite
§4.1 as settled procedure.

The prior owner declined to fabricate a row and that was right — a row asserting a
ratification that did not occur would be worse than the gap.

Adjust the date to the day you actually ratify. One row covers both amendments deliberately:
A1.9 is a non-substantive keying change to the same section, it was coordinator-ratified
within standing authority, and giving it a separate row would assert a distinct ratification
event that did not separately occur.

**Also replace A1.8's status line**, which is stale on either outcome:

- Current: `**APPLIED TO THE WORKING TREE, UNCOMMITTED — text not yet reviewed by the developer.**`
- If ratified: `**RATIFIED.** Committed `7fa0ddf`; ratified <date>, with row `L4` appended to §4.1 in the same act, covering A1.9 (`7e7dc7d`).`
- If declined: `**COMMITTED, NOT RATIFIED.** Text committed `7fa0ddf` and applied to the charter; §4.1 remains a proposal by its own rule until a row exists for it.`

**Optional, and I recommend it:** resolve F2's ambiguity at the source by making §4.1's second
sentence say which reading governs — e.g. *"Any amendment document that changes this charter
must produce a row here, whether or not it changes the binding set."* That converts a rule
requiring judgment into one a validator could eventually check, which is the direction FK-P0
exists to push everything.

## Recommendation

Ratify. The mechanism is sound, the scope limits are real and I checked them against the
authoritative branch, and the only thing between §4.1 and self-consistency is row `L4`.
Declining is coherent too, but then F2 should be carried explicitly as a known-provisional
mechanism rather than left for the next amendment to rediscover.

**The general rule is worth keeping regardless:** a ledger rule must be self-applying — the
instrument that installs it appears in it. Disposition to SPEC-CONVENTION §11.
