Coordinator holds a valid lease and proposes an immutable `DispatchIntent` (application envelope around existing Runtime contracts): goal/parcel/job/attempt IDs, full session/host/tenant/actor identity, mandate/policy/spec hashes, source/base head, workspace/image digest, role, exact requested paths/tools/network, provider/account/model profile, input hash/size/output cap, cost reservation basis, deadline and epoch. Required-field validation rejects missing tool lists and estimates; current generic constraint evaluator otherwise permits some absent values.
2. Transactional admission service on A authenticates the coordinator, checks current lease/mandate scope, validates fresh registry/account evidence, reserves goal+parcel+attempt liability and global call slot in one transaction, and records `prepared`. Reservation facts are signed/bound evidence, not an authority grant.
3. Runtime evaluates the exact intent against owner-issued standing authority, policy and reservation evidence. It emits a sealed durable decision or explicit deny with policy/authority references. Coordinator consumes it; it cannot edit it. A deny releases a never-consumed reservation only with trusted no-send evidence.
4. Runtime execution dispatcher retrieves/verifies the stored decision, requires the matching authority binding, consumes a permission use and persists/read-backs spend evidence. A trusted terminal verifies reservation/attempt/epoch again and atomically marks the effect begun. Only then may the narrow handler launch a worker or send a provider request. Any crash between stages leaves a conservative consumed/held state, not permission to resend.
5. Host broker alone holds Docker, provider and merge capabilities. Workers cannot reach sockets, secret mounts or general host shells. Each subsequent tool/provider call is independently bound to the parent job and remaining allowance, receives a new attempt ID, and passes the same admission checks. No worker delegates outside the broker.
6. Result ingestion binds authentic worker/job/attempt/epoch to source head, artifacts, test commands/counts/exits, raw response hash, model/request ID and usage provenance. Store results before acknowledging the completion event. Duplicate events are harmless. A worker's “done” claim is not acceptance.
7. Independent verifier runs deterministic checks on the exact result/head in a separate read-only input environment. Reviewer returns the substantive contract in BOOTSTRAP.md. Coordinator triages evidence and requests bounded rework. Its reproduction can adjudicate a finding but cannot replace independent review.
8. Merge is a separate admitted effect with exact source/base head, required checks/reviews, closed findings and authenticated repository actor. Changed head invalidates acceptance. Closure records commit/PR, evidence manifest, accounting state and remaining limitations. Cortex receives memories and references via a transactional outbox.

No cross-database two-phase commit is claimed. Ordering is conservative: budget reserve → sealed decision → permission-use spend → begin effect. A crash may consume permission without an effect; it must never produce an effect without permission. Unknown states preserve liability. Fresh authority for a replacement is distinct and bounded; it is never a recycled consumed receipt.

/// <summary>
/// Composed launch-readiness gate.
///
/// Launch mode (<c>KEON_RUNTIME_MODE=launch</c>) must fail fast until every launch-grade lane
/// is delivered, so the host never emits partial or fake launch evidence. Each completed lane
/// moves from <see cref="RemainingBlockers"/> to <see cref="SatisfiedLanes"/>, but launch stays
/// gated while any blocker remains. When the last blocker is removed this gate becomes a no-op.
///
/// Status:
///  - R2A: authority wiring satisfied (real, fail-closed AuthorityService).
///  - R2B: a real controlled execution handler is present (approved execution produces an
///    auditable governed-action side effect). NOTE: this does NOT clear execution — the
///    controlled side-effect ledger is in-memory, so execution durability remains a blocker
///    until R2C. R2B narrows the execution blocker; it does not remove it.
///  - Receipt 1.2: canonical hashing, optional Ed25519 signing primitives, and dispatcher
///    seal verification are implemented. Production signer/key-provider host wiring,
///    mandatory signatures, and predecessor-chain continuity are not.
///  - R2C: durable receipts + execution-durability. R2D/R2E: production signing + chain.
///  - Launch authentication is not implemented.
/// </summary>
internal static class LaunchReadiness
{
    /// <summary>
    /// Launch-grade lanes proven ready. These are recorded for honesty in the failure message;
    /// being satisfied does NOT make launch serviceable while any blocker remains.
    /// </summary>
    internal static IReadOnlyList<string> SatisfiedLanes { get; } = new[]
    {
        "authority: real AuthorityService, fail-closed (R2A)",
        "controlled-execution-handler: approved execution produces a real controlled, deterministic, auditable governed-action side effect via IControlledExecutionLedger (R2B)",
        "receipt-canonical-hash: decision receipt version 1.2.0 is sealed with a canonical SHA-256 hash",
        "receipt-signing-primitives: optional Ed25519 decision-receipt signing and verification primitives exist",
        "dispatcher-seal-verification: controlled execution verifies the stored decision receipt canonical hash and any present signature before execution"
    };

    /// <summary>
    /// Launch-grade lanes still not ready. Authority and the controlled-execution-handler are
    /// intentionally NOT listed (they are satisfied). Execution durability IS still listed —
    /// the R2B controlled side-effect ledger is in-memory and not durable across restart.
    /// </summary>
    internal static IReadOnlyList<string> RemainingBlockers { get; } = new[]
    {
        "execution-durability: the R2B controlled execution side-effect ledger is in-memory and lost on restart; durable execution persistence is not ready (Lane R2C)",
        "durable-storage: decision/execution receipt stores, authoritative receipt outbox, spine events, and controlled-execution state are not durably persisted (Lane R2C)",
        "production-signing: IDecisionReceiptSigner and IDecisionReceiptVerificationKeyProvider are not wired into the API host, and signature issuance remains optional (Lane R2D/R2E)",
        "receipt-chain: receipt 1.2.0 has no prev_hash predecessor continuity or atomic chain-head allocation (Lane R2D/R2E)",
        "authentication: decision and execution endpoints do not authenticate callers or derive tenant and actor identity from verified claims"
    };

    /// <summary>
    /// Throws if any launch-grade lane is not ready. The message names both the satisfied lanes
    /// and the remaining blockers, so the gate stays honest about exactly what is and is not
    /// launch-cleared.
    /// </summary>
    internal static void EnforceOrThrow()
    {
        if (RemainingBlockers.Count == 0)
        {
            return;
        }

        throw new InvalidOperationException(
            "KEON_RUNTIME_MODE=launch is not yet serviceable. Launch-ready lanes: " +
            string.Join("; ", SatisfiedLanes) +
            ". Lanes not yet launch-ready: " +
            string.Join("; ", RemainingBlockers) +
            ". Set KEON_RUNTIME_MODE=harness (default) to run the staging harness. Launch mode will not " +
            "emit partial or fake launch evidence.");
    }
}
