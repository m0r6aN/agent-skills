# Revised charter — Pantheon governed development proof

Revision: OM-PAN-001, proposed 2026-10-19. Supersedes only the provisions named below when ratified. Clinton Morgan is the sole human owner, operator and developer. Keon component ownership identifies software responsibility, not a committee of unavailable human approvers.

## Objective

Make Foreman complete a useful, independently verified Pantheon development cycle under standing authority: refine bounded work, admit a builder through Runtime, execute in Docker, capture artifacts and tests, obtain a substantive independent review, perform any rework, merge an eligible change and close with reconstructable evidence. Restart the coordinator during that cycle without duplicated effects or another approval. Then run one bounded worker on the already identified second laptop using the same custody and admission authority.

Pantheon is a dogfooding implementation of Keon Collective alongside BioStack and other implementations. Cortex is the intended universal memory service; Runtime is the policy decision and enforcement authority. A supported direct Runtime integration is the minimum initial access path. MCP Gateway and SDK adapters remain supported alternatives when their exact source pairs pass conformance. No parallel Pantheon policy issuer, membership registry or memory platform is created.

These refinements are delegated after ratification. A choice that changes purpose, recipients, accounts, hosts, total ceiling, protection level or material risk is an exception. A path spelling, fixture, smaller parcel split, test command, unchanged-cost eligible route or implementation detail within this charter is not another Gate 1.

## Exit criteria

- P-LOCAL: a real Runtime-admitted builder produces a useful change in the Pantheon checkout; independent tests and substantive review identify disposition; eligible merge and closure are completed with a pinned source/config set.
- P-RESUME: custody transfers after a controlled coordinator crash; the old epoch is rejected; completed or uncertain effects are not resent; no human approval is required.
- P-GOV: deny, expiry, budget exhaustion, revocation, stale owner, wrong host, forbidden path and Runtime-unavailable cases prevent effects. Evidence includes decisions, spend barrier, launch, result and merge provenance.
- P-MEM: Cortex receives scoped memories/artifact references and a resumed worker recalls appropriate bounded context; foreign scope is denied. Cortex outage queues projection without granting authority.
- P-B: after P-LOCAL, B executes one bounded test/fixture parcel with authenticated completion, no broad credentials and a stale-fence/disconnect check. No .NET installation is necessary for this initial Node-based scenario.
- P-HUMAN: zero routine approval interruptions between mandate activation and closure. Actual access/authority exceptions are counted separately. Incomplete dispatches, duplicate sends, recovery effort and total spend classes are reported.

GPU rental/donation, federated networking, universal cross-implementation memory sharing, production deployment, digital-entity commissioning and general optimizer work remain future directions. Contracts retain host/profile/tenant IDs and adapter ports so these can be added later without making them first-proof prerequisites.
