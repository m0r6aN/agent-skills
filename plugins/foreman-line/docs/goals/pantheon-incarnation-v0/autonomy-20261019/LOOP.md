# Supported coordinator loop

This directive is proposed. It becomes the goal's active loop directive only after the actual owner ratifies OM-PAN-001 and custody is recorded. The current package's `coordinator-loop.mjs` is a runnable decision kernel with no live ports. `node coordinator-loop.mjs --check` must report `MANDATE_NOT_RATIFIED`; it cannot send, merge or turn booleans into authority. P05 binds the kernel to authenticated Runtime/lease/accounting/result ports and the supported native session mechanism.

## Entry after ratification

Use the installed Foreman `/foreman-line:goal resume pantheon-incarnation-v0` skill (or its supported `/goal resume` alias) after validating loaded source digests. Record the full owner session ID and genuine human message reference. Persist the mandate, revised charter, workflow amendments and queue through the existing goal record; append history, don't overwrite frozen ratifications. Apply the one-time custody transfer and pause the stale-target watcher. Do not ask for another routine approval to perform those ratified steps.

The coordinator then carries out P00's explicit bootstrap, builds the prerequisite path in isolated native worktrees, consumes independent evidence, and transitions irreversibly to Runtime-required execution at P05 acceptance. Missing credential input or external rules become one precise access exception; they do not renew old review authority. Local independent preparation continues while that input is pending.

## Each event-driven iteration

1. Read transactional state, verify mandate/expiry/revocation and acquire/renew the current lease. Reconcile source heads, pending external attempts and completion cursor before proposing any effect.
2. Select a dependency-ready parcel with unblocked authority. Refresh only stale registry/account facts. Split oversized work within scope; pin spec/context/allowed paths, source/image/config and risk. Shaping emits draft ShapingResult; delegated promotion stays a separate verified step.
3. Compare the worker's Step 0 restatement. Exact match proceeds automatically. Scope mismatch gets bounded correction; material authority delta is held and added to the exception batch. A worker never gains scope by restating more of it.
4. Reserve conservative goal/parcel/attempt exposure and call slots. Ask Runtime for the exact decision; consume its authentic stored output. Host broker performs the final epoch/revocation/use/reservation check before launch/send/tool/merge.
5. Wait for durable completion events. No repeated transcript polling. Native wait/completion callbacks or an authenticated event stream are primary; a 60-second supervised reconciliation timer handles missed events. The host persists cursor and wakes the supported session. No terminal-input injection, chat ownership by PID or unverified scheduler claims.
6. Verify returned artifact hashes and exact test environment/counts/exits. An independent verifier runs the required tests. Obtain fresh substantive review(s) bound to the source head; empty/incomplete output is an attempted review, not acceptance. Hold uncertain delivery and never resend it automatically.
7. Triage each finding: reproduce where disputed; fix and rework within two cycles; informational findings retain rationale; accepting material residual risk is an owner exception. A coordinator may refine spec implementation details under the mandate, committing that amendment separately. It cannot widen authority or be the independent reviewer of its own output.
8. Recheck repository rules, actor, source/base heads, required checks and review evidence. Admit merge separately. Merge only the accepted head. Close spec, index, PR and worktree under Stage F; append lessons only with a concrete rule/implementation disposition.
9. Persist accounting and Cortex outbox/memory references. Evaluate each goal exit against actual artifacts. If queue empty but exits are open, report the missing implementation/evidence; never declare success from an empty list.

## Recovery table

| Condition | Automatic disposition | Human exception threshold |
|---|---|---|
| Local syntax/config/test error | Correct within spec; rerun affected checks; preserve first failure | Material design/access change or two exhausted rework cycles |
| Completed truncated/empty review | Mark failed; one fresh larger adequately reserved attempt allowed | Second semantic failure or inability to fit existing budget |
| HTTP drop/timeout/unknown send | Mark unknown; retain reservation; collect supported status/result only | Unresolvable delivery blocks needed work; never auto-repeat |
| Rate limit with known rejected/no-send evidence | Backoff; new attempt only if policy permits and authority remains | Unqualified account/entitlement or repeated cap exhaustion |
| Lease expires/worker disconnects | Deny new effects; successor CAS and reconciliation | Conflicting live owner or corrupt authority state |
| Runtime unavailable | Continue explicit local analysis/tests; hold admission-requiring effects | No recovery within allowed local configuration or changed trust/access needed |
| Cortex unavailable | Retain local transactional outbox; continue scope-safe work | Loss/corruption of only authoritative evidence, or scope cannot be established |
| Repository branch protection requires human | Keep change reviewed; continue independent parcels | One exception naming actual rule, recommended compliant action; no bypass |
| Unexpected price/usage/account/policy | Hold affected profile; retain liabilities; recompute within limits | Increased total ceiling, new account/recipient or material policy change |

Exception report schema: `{id, fingerprint, evidenceRefs, affectedParcels, authorityDelta, attemptedRecovery, recommendedDisposition, safeWorkContinuing, requiredOwnerAction}`. Deduplicate unchanged reports. A check failure is not automatically an owner decision. Count approvals, operational credential interventions, incomplete dispatches and recovery work separately.

Completion writes a final evidence index, actual limitations and final accounting classifications, releases the active lease, closes owned worker channels and stops wakeups. Pending billing reconciliation remains a liability/evidence follow-up, not permission to leave a goal silently active or pretend an invoice exists.
