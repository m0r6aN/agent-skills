## SEAM NOTE
The R1 seam defects are closed from both directions: P1a's `IdentifierAlphabet`/`GrantScopeGrammar` regexes are character-for-character the same T-35 grammar as P1b's `scope.py` (`^[A-Za-z0-9_.-]{1,128}$`; `role:{profile}:{role}` / `profile:{profile}:shared` / `op:legacy`), and because the alphabet excludes `:` and `,`, P1a's comma-join and P1b's comma-split now agree on token identity — the R1 widening payloads (`a,b` in one token; `p:q`/`q:r` collisions) are rejected at P1a binding resolution and, independently, 403'd loudly by P1b's `parse_grant_scopes` (checked at P1b head `9801999`). Composition is fail-closed on every edge I traced: unbound Gateway caller ⇒ `CortexClient` refuses before the wire (so even the collective-handoff lineage read never reaches Cortex); bound caller ⇒ six validated headers whose values cannot carry CR/LF or delimiters; empty `grant_scopes` ⇒ empty carriage header ⇒ P1b "no explicit grants". P1a fixtures now mint grammar-conformant scope ids (`role:operator-developer:role_operator_dev`, `profile:operator-developer:shared`), so the composed grant actually names visible scopes — the R1 concern that no P1a fixture would see a record through the composed system is resolved.
