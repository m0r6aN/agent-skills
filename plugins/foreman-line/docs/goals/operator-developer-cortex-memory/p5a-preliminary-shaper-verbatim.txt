## 4. Missing decisions / amendments (explicit, separate from any draft spec)

- **A1 (T-35/T-36 grammar extension, handoff §4 carry-forward):** add `handoff:{profile_id}:{role_id}` and `cap:curation.approve` to `GrantScopeGrammar` in `Auth/RoleBinding.cs`; keep `\A…\z` full-string, no trimming; `cap:` acceptable only via issuer-validated JWT `grant_scopes` or enrolled `MachineEnrollmentRecord.GrantScopes` (structurally the only two binding sources — state this in the amendment text); fixtures in `RoleBindingTests.cs` (accept own-role handoff token, accept cap from both sources, reject malformed/foreign variants; T-36 trailing-LF/whitespace cases). Without A1, curation approve and handoff flows are unusable: the Gateway fail-closes tokens Cortex P4a already accepts.
- **A2 (test-surface collision):** `MockCortexServer.cs` must additively gain `/v1/recall`, `/v1/memory-events`, `/v1/curation/*`, `/v1/evidence/verify`, `/health` routes **and** backend `tenant_id`/scope fields on shard rows; `CortexReadHandlerTests.cs:72,285` currently pin the caller-synthesized `tenant_id` defect and must be re-pinned to backend ownership (and new fail-closed cases added). Alternative without amendment: self-contained private doubles inside `ProtocolContractTests.cs` — rejected as recommendation (duplicates an entire server; still leaves `CortexReadHandlerTests` red after T-8). A2 is **blocking** for P5a-1.
- **A3 (explicit binding threading):** handoff requires threading `X-Keon-Operation-Id` and the binding explicitly instead of `RoleBinding.Ambient`. `CollectiveHandoffDispatchHandler.cs:103` calls `GetShardAsync`; a signature change collides. Coordinator must either grant the file or rule "additive overload, ambient retained for collective this parcel" (recommended default: grant the file — one-line call-site adaptation, removes a dual-authority seam).
- **A4 (T-34/OD-22 producer chain):** manifest says P5a "may own" the spine amendment but does not list `IngressSpine.cs`. The chain freeze needs: outcome payload gains an immutable `invocation→target→execution→result` linkage (directive/intent/decision receipts already exist; the missing links are `target_ref` identity and an execution-result distinction), a `completed` terminal value distinguished from governance `approved`, and honest null execution receipt for denied/decide-only paths. **Until A4 lands and is frozen, every outcome/attribution event stays `self_reported`, `approved` is never translated to `completed`, and the Gateway event handler must forward `self_reported` (or rely on Cortex's 422-on-`supported`)** — this is the existing approved state, NOT completed; P5a must not manufacture execution evidence. If A4 is deferred, P5a-4 still ships with fail-closed `self_reported`-only semantics and the three checklist fixtures (`decide_only`, completed-failure-reported-as-success, receipt-replay-against-another-target/profile) asserting refusal of escalation.
- **OD-23:** remains provisional. Gateway curation handler passes `approval_receipt_ref` through **unverified**, never mints/validates it, and surfaces Cortex's provisional support level unchanged; a verified-receipt path is P8. No spec text may imply otherwise.
- **Collisions:** `CortexClient.cs` and `Program.cs` appear in all four subparcels → strictly serial order above; no parallel dispatch. `IngressSpine.cs` is also P1a-owned historically — serialized handoff rule (T-2) satisfied since P1a is merged at this base.
