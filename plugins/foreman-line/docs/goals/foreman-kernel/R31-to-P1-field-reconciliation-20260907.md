## Concrete preactivation dispositions recommended

These recommendations require coordinator recording and field-shape review; this document does not silently change the approved draft.

**F01 — Preserve two canonicalization domains.** P0 `canonicalJson` sorts object keys and NFC-normalizes string **values** recursively; object-key spelling is not normalized. `sha256` returns untagged lowercase hex. P1 explicitly prohibits Unicode normalization and proposes domain-wrapped canonical JSON over safe integers. They are not interchangeable. Preserve P0 bytes/digests for every imported SourceRef/binding; give P1 its own strictly bounded, nonnormalizing canonical encoder in the new package. Recommend the previously unspecified P1 tag spelling `sha256:<64 lowercase hex>` for new P1 digest fields, with explicit encode/decode at the boundary, never retag/recompute upstream stored references in place. Keep P1's `{domain,apiVersion,payload}` domain separation. Golden vectors must distinguish composed/decomposed values, object-key spelling and arrays, while proving embedded P0 reference values remain unchanged. No P0 helper alteration is needed. [P0 canonicalization](https://github.com/m0r6aN/agent-skills/blob/521214e4fa7e3475e2544ef1f1492638250437f6/plugins/foreman-line/authority-registry/src/validate.ts#L819); P1 Constraints, numeric/digest rules and P1-S08.

**F02 — Keep source assurance separate from runtime assurance.** P0 has `narrative | structural | detected | mediated | independently-verified | human-ratified`. P1 proposes `structural | mediated | detected-only | ci-enforced | human-judgment | unsupported-host | degraded-read-only`. No total string-renaming function is sound. Recommend preserving the exact P0 resolution assurance/owner/classification in a typed upstream-policy evidence component of admitted decision results, while deriving P1 `assuranceLevel` independently from evidence for that request. P1 contract fixtures claim structural only. Do not add source-ratification labels to the runtime union merely to make a cast possible. [P0 assurance union](https://github.com/m0r6aN/agent-skills/blob/521214e4fa7e3475e2544ef1f1492638250437f6/plugins/foreman-line/authority-registry/src/types.ts#L61); P1 assurance paragraph and P1-S11.

| P0 label | Permitted relationship to P1 |
| --- | --- |
| narrative | Source provenance only; no runtime assurance conversion |
| human-ratified | Ratified source intent only; does not establish human-judgment outcome, gate completion or runtime satisfaction |
| structural | Consistent with structural-only checks when the P1 check itself establishes them; does not authenticate admission |
| detected | Candidate detected-only evidence category only when current subject/run/producer evidence is validated |
| mediated | Candidate mediated category only with actual applicable host/process evidence; label alone insufficient |
| independently-verified | Requires inspection of producer, subject, mechanism and evidence; cannot blindly map to human-judgment or ci-enforced |
| No P0 equivalent | unsupported-host and degraded-read-only are P1 runtime posture outcomes, not assurance promotions from source metadata |

**F03 — Specify protocol-error and admitted-decision variants separately.** The draft requires principal/inputDigest/policyDigest in DecisionEnvelope but also forbids disclosure or context lookup after failed admission. Preserve the existing semantics by defining DecisionEnvelope only for the authorized decision stage; define a separate closed protocol-error variant for malformed/version/admission/internal failures with bounded safe code/diagnostic and only transport-safe correlation fields. No synthetic trusted principal, goalRevision, policy/input digest or gate metadata on that error. Exact error variant fields and registry-failure mapping remain Step0 decisions; recommend explicit non-gate internal policy-resolution codes or a typed retained P0 reason, rather than mapping REGISTRY_INVALID to GATE_NOT_SATISFIED. This is a real shape gap, already anticipated by P1-S10/R02, not an implementation request.

**F04 — Do not equate principal, role, operation scope and operation ID.** Examples: admitted `human-developer` projects to role `developer`; `independent-reviewer` to `reviewer`; `ci-service` to `ci`. `kernel-operator` requires explicit context-specific role selection, not automatic widening to both kernel and operator. Anonymous content has no control query. Query operation `repo-mutation` is a scope category, not the governance ID `gate3.merge` or a future control-tool ID. Step0 must publish a finite trusted projection table for each supported operation; the future admitted operation set remains distinct from the seven governance rows. Unknown projection fails closed. None of this requires adding a P0 API or public runtime enum export.

**F05 — Finish exact schemas without changing chosen behavior.** Full discriminant fields, required/optional constraints, evidence-reference variants, obligation payloads, schema IDs/refs and policyDigest preimage remain intentionally unfinished in the prose spec. Recommended policyDigest preimage is a separately versioned P1 policy identity including accepted registry identity/content pin and effective policy/configuration identities; sourceSnapshotCommit alone is insufficient. Scope digest remains P2-owned and goalRevision state-owned. The exact runtime-code mapping, 64-entry overflow behavior, shadow-only metadata and APPLIED/NOOP consumer variants must be presented together in Step0, not inferred from the broad P0 Decision union. Pin dependency/import choices only after merged P0; P1 may describe these shapes without implementing P12/P13 adapters or importing unpublished exports.

## Coordinator disposition — September 7

Under the recorded September 7 ratification and blanket authorization, F01–F04 are accepted as preactivation compatibility requirements. New P1 digests use `sha256:<64 lowercase hex>` and their own nonnormalizing domain-separated encoding; embedded P0 references retain their original values and digest semantics. Source assurance and runtime assurance remain separate. Protocol errors have a closed trust-safe variant distinct from admitted DecisionEnvelope. Principal/role/operation projection is finite, trusted and fails closed on unknown mappings; no role expansion is inferred from a principal label.

F05 remains the explicit Step0 field-table obligation, including exact policyDigest preimage and protocol-code mapping. These choices must be incorporated in the P1 preparation contract and independently reviewed with exact fields before implementation dispatch. This disposition does not claim that those schemas or adapters exist. It does not change the frozen R31 source/package, transfer ownership, accept R31 before its full chain/reviews, satisfy human Gate 3 or remove P1's actual merged-P0 dependency.
