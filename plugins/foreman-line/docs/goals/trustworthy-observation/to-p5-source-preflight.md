P5-1 REQUIRED: exact resolver/default-path eligibility must precede execution or runnable copy.
Approval resolve-input defaults docs/specs/active; approval CLI calls resolveArtifact with only repoRoot and optional epicTitle, never specsDir. Console config.specsDir may be plugins/foreman-line/docs/specs; finding a valid artifact there does not make frozen bare-slug CLI resolve it. The direct-path resolver branch is not reachable through frozen lowercase slug argv and cannot serve as a bypass. Passing a plugin specsDir only to an internal resolver would validate different behavior from the actual command.
Ruling: validate actual selected projected artifact with shipped readShapingResult; require frozen bare-slug resolveArtifact(slug,{repoRoot}) to identify exactly that same existing artifact with wasProjected:false. Never pass epicTitle or projection options. Home plugin default mismatch remains withheld, even if an unrelated native same-slug artifact exists; no arbitrary-path arg/flag/new adapter. Eligibility must be grounded again at request time before invoke spawn, not assumed from an earlier remedy observation. State race limits honestly; no atomic snapshot guarantee.

P5-2 REQUIRED: exact candidate join and uniqueness cannot derive from parcel capitalization or display winner.
Current remedy gate2 uses parcel.parcel directly in `approval approve`; uppercase keys fail lowercase slug grammar. Current projection picks spec/display chain winners and flags duplicate-chain but does not provide a complete projected-artifact resolver. Actual projected basenames and shipped payload/spec refs must identify a unique artifact for the selected parcel/root. Display winner, specRef basename, alias or case conversion is insufficient authority to mint a slug.
Ruling: define exact candidate search/join over selected active/done projected files with actual basename and original spec refs. Multiple candidate artifacts, malformed/unreadable candidates or ambiguous joins must withhold rather than filter into a false unique match. Candidate in done still cannot resolve by frozen default-active bare slug unless actual exact same target is reachable; no fallback to different file. Do not expose arbitrary directory listing or expand scan/project/types scope silently: if handoff cannot derive needed identity in <=5 current allowed source files, amend exact scope before code or withhold.

P5-3 REQUIRED: distinguish approve requirements from reject and dispatch absence.
Approval CLI runApprove requires nonempty owner --approver, interactive TTY and typed exact-slug confirmation. Frozen approval argv cannot include --approver, so a complete runnable approve copy cannot be emitted by inventing a name/flag. runReject permits omitted reason (null), requires neither approver nor approve's TTY/confirmation, but it writes a rejection record and is always presentation-only. Draft sentence grouping approve/reject with approval's requirements risks incorrectly telling reject users they need approve's inputs. Dispatch package has no bin/CLI entry; executeDispatch is a side-effectful library API, not a command callable with frozen argv.
Ruling: retain frozen structured argv and per-flow truthful explanations. Approve incomplete command withheld; reject never executed and optional reason never invented; readable supported reject may be presented only with honest mutator wording. Dispatch runnable command withheld with no-bin reason; no TS library import invocation or invented `dispatch approval-cli` executable. Neither advisor nor verifier may execute mutators to test eligibility.

P5-4 REQUIRED: primary-root authority context is lost in treeConfigFor.
API /api/invoke currently always calls invokeFlow(primary config); repo-root args are checked against that config and validation paths against primary receiptsDir. Advisor /api/remedies uses treeConfigFor, which replaces repoRoot/specsDir/receiptsDir with selected extra tree while preserving other config fields. A shared helper receiving only selected config can mistake that extra root for the primary root. Standalone invokeFlow called with a selected tree config likewise does not possess an immutable primary identity.
Ruling: define explicit primary-vs-selected context without adding config.ts to scope implicitly. API invoke retains primary config; advisor needs an explicit executionEligibility input or selected-root identity compared with original primary context (API optional path can pass it). Extra-root handoffs remain presentation only even if all target checks succeed. Do not infer primary from alias null, pluginRoot, stateDir or selected config.repoRoot. Refused extra-root requests must still be audited once; no extra-root state writer or registry extension.

P5-5 REQUIRED: validation grounding must use actual uniquely mapped workflow, not roots or selected display winner.
failedRemedy currently emits receipts validate <repoRoot>/docs/receipts/ (whole receipts root, also wrong for plugin layout), whereas invoke receipts-path requires a UUID workflow directory or matching member. Accepted INV requires exact unique mapped workflow directory, not an arbitrary member or every chain in a root. Duplicate-chain remains flagged despite display winner; unmapped has no parcel target.
Ruling: canonical target from selected actual receiptsDir + unique mapped workflowId, with parent P2/P3 diagnostics and duplicate flags preserved. Advisor withholds unavailable/duplicate/unmapped target. Direct invoke needs the same actual mapping/ambiguity eligibility proof, not syntactic UUID validation alone; determine how to discover mapping within bounded handoff/API scope before activation. Do not use legacy chain.locator or root-qualified alias as a path. Preserve allowed frozen validation argv only; any decision to tighten previously syntactically accepted direct member path requires explicit accepted-INV disposition, not accidental handler behavior.

P5-6 REQUIRED: copy commands must ground code paths AND cwd as well as quote argv.
Current renderCommand joins argv with spaces and displays fictional PATH prefixes, while actual spawn uses process.execPath, absolute console-installed tsx CLI and absolute shipped approval/receipts CLI, cwd=config.repoRoot, minimal SPAWN_ENV, no shell. The command copy must use that actual executable/code binding; selected extra data root must never redirect code loading. A relative receipt argv works only under configured cwd; quoting it perfectly does not make a paste in arbitrary terminal directory equivalent.
Ruling: shared read-only binding descriptor holds executable, absolute prefix args, frozen request args, actual cwd, runnable/present/withheld reason. Preserve original request argv/audit unchanged; do not silently canonicalize its slots. Either bind copy cwd safely with an explicitly reviewed shell wrapper/prerequisite or withhold incomplete relative-path copy while retaining structured argv+cwd metadata. Every executable and argument individually single-quoted, bash/zsh/fish apostrophe close + double-quoted apostrophe + reopen, PowerShell doubled apostrophe and call operator `&` for quoted executable. cmd.exe copy withheld with reason. Newlines, dollar/backtick/substitution text remain literal argument data; no shell spawn. Runtime-dependent environment/copy limitations must be explicit, not claimed identical to minimal-env subprocess execution.

Editor references may use only actual designated parent-P4 paths with verified editor binding; $EDITOR is an unknown multiword environment command, not a grounded quoted executable. No new editor/gh flow or mutation authority. Optional UI/API work should be committed as necessary exact scope when exposing structured argv/shell withholding; do not claim all strings executable when metadata says otherwise. P1 unknown remedy's empty commands/source explanation must stay intact.
