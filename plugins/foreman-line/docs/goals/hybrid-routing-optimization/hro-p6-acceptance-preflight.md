## Proposed public smoke workload and deterministic quality rubric

The smallest useful proposed workload has three independent public text cases,
with identical prompts within each cold/warm pair. It tests a narrow controlled
text lane, not general coding ability, model superiority or frontier-tier quality.
The exact UTF-8 prompts, system message, output comparison rules and order must
be frozen in the eventual reviewed artifact before the first provider call.

Proposed system message: "Follow the user's output format exactly. Do not use
tools or add explanations."

| Case | Proposed user prompt | Required result |
|---|---|---|
| Arithmetic | Return only the base-10 integer equal to 17 * 19. | 323 |

## Proposed six-attempt comparison

Plan three cold/warm pairs in the listed case order: one fresh process for a
case's first governed invocation, followed by the same prompt in that process
with a distinct predeclared intent and fresh selection. Every inference, including
any warm-up, counts toward the six-attempt cap; there is no unmeasured warm-up.
No inference retries or model substitutions are part of this minimal comparison.
An uncertain charge stops that dependent pair/batch under the real ledger rules.
A later resumed batch must preserve prior liabilities and failed observations.

The accepted user entry currently lacks the completed composition needed to run
such pairs. The future protocol must prove genuine one-shot entry/intent custody
for each invocation in a shared process. It must not bypass entry authorization,
reuse a consumed proof or create fresh storage to reset budget/admission limits.
If the reviewed entry cannot support this protocol, amend the protocol before
execution instead of calling two fresh processes a warm process.

Cold is the declared baseline for process/schema warm-up only. Keep exact model,
provider endpoint, policy, runtime/catalog/profile versions, thinking level,
payload and output bounds fixed within a pair. Refuse or mark incomparable when
those change. Record provider-cache counts as observed/unknown; never attribute
provider cache effects to local schema reuse. Use a monotonic common invocation
interval and record process startup separately if available. Report all six raw
observations and paired differences; with three pairs, do not imply statistical
significance or a universal performance claim.

This baseline does not reconstruct the retired routing implementation or prove
historical model-spend savings. Do not restore retired execution paths. A broader
before/after savings claim needs a separately frozen safe baseline and comparable
evidence. An honest result can be no demonstrated savings.
