# CCM implementation lessons

## P1D

Use typed pg_settings enum metadata and installed extension namespace to establish iterative HNSW; a raw GUC string is weak evidence. Keep ordinary query failure unavailable, not a guessed capability result. Real fresh read-only sessions on a disposable synthetic DB verify library loading and nondefault schemas; they do not qualify a remote profile or prove SLOs.

## P1C

Strict consumer parity requires actual accepted producer predicates: imported clean text and numeric literals differ from broad heuristics. Reproduce reviewer hypotheses before assigning repairs. A fixed byte fixture plus retained test identities and targeted cross-language probes complements independent source review; record/reflection compatibility and strict-vs-local serializer boundaries remain explicit.


## P2A

Freeze scanner work budgets before repair; bound candidates before allocation and scalar bytes before whole-tree serialization. Independently prepared HMAC vectors plus exact boundaries expose defects that implementation-mirroring tests miss. Reproduce complexity hypotheses: the original JWT lookbehind matters, while greedy scheme scanning and repeated assignment ends had actual bounded timeouts. Ask independent reviewers for compact completed verdicts: long narrative targets consumed output on reasoning and truncated two answers; one explicitly admitted8192-token/500-word pair completed more cheaply. Incomplete PASS fragments never approve a parcel. Preserve failed-call holds and failed CI; diagnose inherited clock assumptions with controlled synthetic time before a single same-head rerun.
